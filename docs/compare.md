## 各方案優缺點摘要

### 1. SQLite
* **優點**：Python 內建 `sqlite3` 模組、零設定與免額外安裝資料庫伺服器、單一檔案便於版本控制測試與攜帶。
* **缺點**：高併發寫入鎖定（Write Lock）限制，不適合大規模多人同時寫入的雲端環境。

### 2. PostgreSQL
* **優點**：支援 `JSONB` 與高併發 ACID 交易、擴充性與資料完整性極佳。
* **缺點**：需要額外啟動資料庫服務或 Docker 容器，本地開發與助教批改測試環境配置較繁瑣。

### 3. MongoDB
* **優點**：原生 JSON/BSON 文件結構，可直接存放巢狀的 `position` / `rotation` / `scale` 向量物件。
* **缺點**：需要獨立伺服器或雲端 Atlas 帳號，且對於強結構化的 CRUD 專案較為厚重。

## 最終選型與理由

**最終選擇：SQLite**

1. **零依賴與可重現性最高**：Python 內建支援，任何人 clone GitHub repo 後不需安裝額外資料庫或 Docker，即可直接執行 `uvicorn` 與 `pytest`。
2. **完全滿足 XR 場景物件資料結構**：3D 物件的欄位（`name`、`model_url`、`position`、`rotation`、`scale`）結構固定，搭配 Pydantic 驗證與參數化 SQL 查詢即可兼顧安全與效能。
3. **未來平滑升級**：若未來需要多人線上協作擴充，可透過抽換資料庫連線層無痛遷移至 PostgreSQL。
